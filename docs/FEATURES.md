## 1. 全局与基础能力（✅ 已完成，改动需谨慎）

### 1.1 后台记录保存（`utils/sync.js` + `utils/store.js` + `utils/ui.js`）
- ✅ **先渲染后拉数据**：启动即读本地缓存渲染，杜绝白屏；云端数据到达后增量刷新
- ✅ **写队列 + 乐观更新**：所有增删改先写本地立即生效，再排队上送；失败保留队列 **15 秒自动重试**，不静默丢数据
- ✅ **手动重试有反馈**：离线横幅点「重试」走 `ui.retryWithFeedback`，先出遮罩加载态，再按 `sync.pull()` 的返回值提示「连接已恢复」或「仍无法连接，请稍后重试」；不再把 `onPullDownRefresh` 当点击事件直接绑定
- ✅ **写入防重复**：`ui.isRepeatedTap(page, key, wait)` 在**校验通过、真正写入之前**去重，同一目标的连续点击不产生语义重复的记录；勾选/完成这类切换语义的操作按目标 id 分键去重，计数型打卡不节流（连点累加是预期行为）
- ✅ **按压反馈**：整块卡片用 `record-card` + `record-card-pressed`；悬浮按钮、列表行、设置行、月份箭头等用 `tap-row` + `tap-pressed`（微信 `view` 默认 `hover-class="none"`，必须在模板显式声明）
- ✅ **增量拉取**：`GET /api/sync?sinceSeq=&generation=` 按服务端变更序号拉取，旧客户端可使用 `since`
- ✅ **实时推送**：WebSocket `/ws` 收到变更通知后 1.2s 防抖拉增量；断线指数退避重连（5s→30s）
- ✅ **兜底轮询**：60 秒定时拉一次；网络恢复事件触发即时重连+冲刷
- ✅ **冲突策略 LWW**：客户端时间戳 `updatedAt` 大者赢；被拒时以服务端返回值回写本地
- ✅ **软删墓碑**：删除不物理删，换设备也能收到删除事件
- ✅ **登录态保护**：首屏不静默登录；token 失效时清除本机登录态，等待用户重新点击登录
- ✅ **本地缓存体量保护**：记录快照与写队列分别落在 `wb_life_state` 和 `wb_life_queue`；微信单 key 上限 1MB、合计 10MB（官方文档）。写前估算体积，超阈值先做无损瘦身（丢弃超过 7 天的墓碑，服务端仍保留墓碑并会下发）；写入失败记录 `persistError` 并通知页面，由「我的 → 数据状态」提示用户导出备份后重建；`queue`（未上送的写）在任何情况下都不裁剪
- ✅ **本机缓存重建**：完整拉取后叠加待同步与被拒写入，成功后原子替换本机快照；用于缓存异常或占用过大时自救
- ✅ **本地缓存**：key 统一前缀 `wb_life_`；防抖 250ms 落盘
- ✅ **全局异常留痕**：`app.js` 捕获 `onError` / `onUnhandledRejection`，保留最近一次异常（令牌与 code 打码、截断 180 字）供「我的」页展示，**不上报任何远端**；异常只用于本地诊断，与隐私政策一致

### 1.2 数据模型（12 个同步集合）
| 集合 | 字段 | 说明 |
|---|---|---|
| money | `type`(expense/income/transfer)、`amount`、`category`、`date`、`note`、可选 `accountId`；转账另有 `toAccountId` | 转账不计入收入或支出 |
| accounts | `kind`(asset/liability)、`name`、`openingBalance`、`manualAdjustment`、`category`、`note`；旧 `balance` 继续兼容；负债可填 `statementDay`、`dueDay`、`minimumPayment`、`currentBill` | 余额由期初＋流水＋校准推导；仅手工输入 |
| habit | 定义：`kind:'def'`、`name`、`mode`(check/count/value)、`target`、`unit`、`color`、可选 `pinned`；打卡：`kind:'entry'`、`habitId`、`date`、`value` | 两类记录共用集合 |
| plan | 旧事项：`title`、`date`、`time`、`done`、可选 `pinned`；重复源：`kind:'series'`、`startDate`、`repeat:'daily'/'weekly'`、`endDate`；覆盖：`kind:'occurrence'`、`seriesId`、`date`、`done/skipped` | 日程；旧记录无需迁移 |
| fitness | `kind:'weight'`、`date`、`weight`、`bodyfat`；周计划：`kind:'plan'`（v1.4 定义） | 体重+计划 |
| shopping | `name`、`note`、`done`(Boolean)、可选 `pinned` | 待买 |
| media | `kind`(book/movie/music)、`title`、`status`(wishlist/doing/done)、`rating`(0-5)、`comment`、`date` | 书影音（纯文字卡片） |
| settings | 固定 id=`app`：`budget`(月预算)、`categoryBudgets`(分类预算)、`aiConsent`(用户主动开启 AI)、`theme`(`forest`/`paper`/`sky`/`violet`/`night`/`auto`)、`habitReminderEnabled`/`billReminderEnabled`(提醒矩阵开关，v2.11)、`habitReminderTime`('HH:MM'，默认 20:00)；预留：`height`、`targetWeight` 等 | KV 配置；主题随设置同步 |
| memories | `content`(≤1000 字)、`occurredAt`(本地时间)、可选 `mood`、`tags`(≤3) | 纯文字随记；不支持图片、音频或文件；可由服务端裁剪为 AI 洞察摘要 |
| focusSessions | 开始时间、日期、计划时长、实际分钟数、状态、可选关联日程 | 本机计时可继续，已保存时段参与复盘 |
| weeklyReviews | 周起始日期、回顾内容和下周调整 | 私密周复盘 |
| moneyRules | 带生效日期的周期账单版本 | 每期可确认或跳过 |

账号资料不进入同步集合：服务端 `users` 表保存昵称；历史版本已保存的掩码手机号保留以兼容旧资料，不再请求、更新或用于找回账号。头像照片位于服务端私有目录，同账号可跨设备读取。未设置照片时使用昵称生成的文字头像。

### 1.3 登录与隐私授权
- ✅ 首屏必须由用户点击「微信登录并开始」触发 `wx.login`，应用启动不静默创建登录态
- ✅ 登录前需阅读并同意用户服务协议和隐私政策；协议/第三方说明可在「我的」页再次查看
- ✅ 昵称使用 `input type="nickname"`，用户可选择微信昵称或手动填写；照片可在资料页选择，默认头像由昵称生成
- ✅ 微信登录成功后可直接继续；昵称允许留空
- ✅ 后端拒绝资料更新中任何新的 `phoneCode`（422 `phone_binding_disabled`）；历史 `phone/hasPhone` 字段和资料响应格式保持兼容
- ✅ 退出登录清除本机缓存，云端数据保留；登录态失效时停留在登录页等待用户重新操作
- ✅ 登录传输失败按 cronet 语义分类（`-101` 重置 / `-102` 被拒绝 / `-118` 超时，符号名优先于数字码），最多 5 次尝试、退避约 8.2 秒，每次重试都重新获取 code；已拿到 HTTP 状态码的错误（401/429/5xx）不重试
- ✅ 登录失败后提供只读「网络自检」：仅 `GET /api/health`，不带登录令牌、不写本机缓存，用于区分「服务端整体不可达」与「仅登录失败」；失败态同时展示构建版本便于报障，重试与自检都由用户点击触发
- ✅ **分享卡片隐私（v2.6）**：转发与朋友圈卡片只用固定中性文案（不含金额符号或数字，也不读取任何本机记录），并显式指定包内 logo 作为分享图——避免微信默认以「当前页面截图」当卡片，记账页与时间线截图会带出用户自己的数据

## 4. 服务器端功能点

### 4.1 现有 API（✅ 已实现，`server/server.js`）
| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/login` | POST | `wx.login` code 换 token；生产端超时为 10 秒；仅「无 HTTP 响应」的传输失败（连接重置 / 被拒绝 / 超时）重试，最多 4 次、退避约 8.2 秒，每次重试都重新获取 code |
| `/api/profile` | GET/PUT | 读取账号资料；PUT 接受昵称；任何新的 `phoneCode` 请求返回 422，历史掩码字段保持兼容 |
| `/api/profile/avatar` | GET/PUT/DELETE | 读取、上传或清除当前账号的头像 |
| `/api/sync?sinceSeq=&generation=` | GET | 按服务端变更序号返回增量、游标和代次，兼容旧 `since` |
| `/api/reminders` | GET | 分页查询当前账号的提醒任务 |
| `/api/memories/deleted` · `/api/memories/:id/restore` | GET · POST | 查看最近 30 天删除的随记及恢复指定版本 |
| `/api/insights?scope=today\|month` | GET | 登录态保护的 AI 轻提醒 / 月报一句话；只返回当前用户结果，按周期缓存 |
| `/api/records/:collection` | GET | 单集合全量（首装兜底） |
| `/api/records/:collection/:id` | PUT | 幂等 upsert，LWW 校验 |
| `/api/records/:collection/:id` | DELETE | 软删墓碑 |
| `/api/reminders/capabilities` | GET | 当前登录用户可否使用订阅提醒及模板 ID；v2.11 起扩展返回 `habit`/`bill` 两类（`enabled`/`templateId`/`credits` 剩余额度），原 `enabled`/`templateId` 字段保留不变 |
| `/api/reminders/:planId` | GET/PUT/DELETE | 查询、创建/重排、取消单次提醒（需登录态） |
| `/api/reminders/credit` | PUT | v2.11 订阅额度上报（`{kind:'habit'\|'bill'}`，需登录态 + 限流）：授权成功后 +1，服务端发送成功后扣减；一次订阅对应一次触达 |
| `/api/account` | DELETE | 需一次新的微信登录 code，删除账户全部专属数据 |
| `/api/health` | GET | 健康检查；正式版不返回数据库名或开发模式 |
| `/ws?token=` | WS | 变更广播 + 30s 心跳 |

存储：默认 Docker MySQL（数据库名 `life_workbench`，`server/db/schema.sql` + `npm run db:migrate`）；保留 `STORAGE_DRIVER=file` 兼容旧 JSON 数据和离线测试。同步协议不依赖具体存储实现，未来可用 MySQL dump 迁移到服务器。

## 7. 域名 / SSL / 备案（后续购买）衔接清单

**绑定前你现在就能做的**：全部开发与真机调试——开发者工具勾选「不校验合法域名」+ 手机开启调试模式，功能可在开发环境测试（后端先 `npm start` 跑在本机/服务器 IP）。正式审核与发布仍需真实 HTTPS 域名和后台配置。

**购买后只需四步**：
1. 确定实际运营主体、域名和服务器接入商，并按所在地与接入商要求完成适用流程 → 解析到服务器
2. SSL：Caddy 自动签发（免费），或云厂商免费证书 + nginx
3. 小程序后台「开发设置→服务器域名」配置 request 为 `https://api.你的域名`，socket 为 `wss://api.你的域名`（不带端口不带路径）
4. `server/.env` 改 `DEV_MODE=0` + AppID/AppSecret + 订阅模板 ID 并重启；在 `miniprogram/config/runtime.js` 的 `PRODUCTION_API_BASE_URL` 填正式域名重新编译 → 提审（工具类目）

具体成本、备案/审核周期与主体要求取决于域名、服务器地区、接入商和微信后台当期规则；以 [RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md) 为发布执行清单。
