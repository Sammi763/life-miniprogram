## 0. 摘要：结论先行

**总体判断**
我们不是任何一个竞品的同类。竞品是**垂直单点冠军**，我们是**一体化聚合器**。所以正确的问题不是「谁功能多」，而是「单点深度差多少、聚合价值值不值」。

**最大风险**
在每一个垂直维度上，我们都**不是最好的那个**：记账不如钱迹、打卡不如小日常、待办不如滴答清单、专注为零。用户没有任何「非你不可」的理由——一体化只有在**跨模块联动**真做出价值时才是优势。

**最大缺口（P0）**
**提醒/推送能力几乎为零**——只有「未来单次带时间的日程」能发一条订阅消息。竞品的留存引擎（打卡提醒、记账提醒、还款提醒、常驻提醒）我们全没有。

**最大优势**
**跨模块的「今日 + 月报 + 统一搜索」闭环**，以及**真正数据自主**（自建后端、全量导出、无广告、AI 默认关闭）。这 6 款里没有任何一款把「财务 + 习惯 + 生活」合成一页。

### 三条核心判断

1. **深度输、广度赢，但广度尚未变现。** 六大模块（记账 / 习惯 / 日程 / 随记 / 待买 / 书影音 / 健身）单看都只是竞品的 40–70% 完成度；但「今日页把日程+习惯+待买合成统一待处理」「月报把收支+习惯达标率+体重+书影音+心情合成一页」是竞品没有的结构。这张牌目前只做了一半——**联动只做到了「聚合展示」，还没做到「互相驱动」**（例如：记账超支 → 自动收紧待买清单预算；习惯连续中断 → 日程自动降级）。

2. **「数据自主」是我们唯一不打折的差异化，但兑现不完整。** 自建后端 + 写队列 + 墓碑同步 + 全量 JSON 导出 + 无广告无社区，客观上比鲨鱼/喵喵（广告+导流+投诉）干净得多。但**导出只有 JSON、没有导入**——用户拿不走也搬不回，承诺断了一半。钱迹已做到「支持几乎所有主流记账软件导入」。

3. **微信小程序这个载体，同时是最大优势和最大天花板。** 优势：零安装、即用即走、12 页转发/朋友圈，对小红书冷启动引流是天然通路，获客成本远低于要求下载 App 的竞品。天花板：**桌面小组件、自动记账（读系统通知）、学霸模式锁机、Apple Health/iCloud、后台常驻提醒——这五项在小程序架构里都做不了**，而它们恰好是钱迹（自动记账）、番茄 ToDo（锁机）、小日常（小组件）的核心卖点。

## 3. 不足：做了，但明显不如竞品

只列「同一件事我们做了、但做得更弱」的项，按杀伤力排序。

| 优先级 | 不足项 | 我们的现状 | 竞品做到什么程度 |
|---|---|---|---|
| **P0** | **提醒 / 推送几乎为零** | 只有「未来 + 带具体时间 + 一次性」的日程能申请一条订阅消息（`plan` 集合）；习惯打卡、每日重复日程、待买、账单还款到期**全部无推送** | 小日常柔性提醒（不弹红点、次日温和提醒）；滴答清单单任务最多 5 个提醒 + 常驻提醒（不完成一直响）；番茄 ToDo 常驻提醒 + 定时锁机；鲨鱼默认每天 19:00 记账提醒 |
| **P0** | **分类固定，决策成本反而更高** | `finance.js` 写死 **28 个支出分类 + 11 个收入分类**，用户不能增删、排序、换图标，无二级分类。想改分类要改代码 + 提审 | 钱迹支持自定义一二级分类名称与排序、自定义图标、自定义月起止日；鲨鱼/喵喵至少可自定义部分图标 |

| **P1** | **记账没有日历视图，报表形态单一** | 月报有收支汇总 + Top3 分类 + 每日趋势；记账页是「流水 + 月度柱状」 | 钱迹/鲨鱼有收支日历视图；钱迹有饼图/条形图/折线图 + 按年/月/自定义区间统计 + 单分类详统 |
| **P1** | **没有深色模式** | 4 套低饱和主题（雾林/暖纸/月白/暮紫）都是浅色系；`FEATURES.md` 中深色模式仍标 🚧 | 这 6 款**全部**支持深色/夜间模式。这项缺失在夜间使用场景里非常显眼 |
| **P2** | **没有应用锁** | 无密码、无手势、无指纹（小程序也拿不到指纹） | 钱迹免费版即含密码保护；鲨鱼手势/指纹需付费但门槛很低 |
| **P2** | **日程能力太薄** | 日程只有 `title / date / time / done / pinned`，无子任务、无优先级、无标签、无过滤器、无备注 | 滴答清单：子任务/清单/文件夹/优先级/标签/过滤器/多提醒/NLP 自然语言输入 |

## 4. 缺失：整个能力类别我们都没有

这些不是「做得弱」，而是「没有」。标注 `载体受限` 的项在微信小程序架构下**无法实现**，只能靠做 App 解决。

### 财务侧缺失

- 账单导入（微信 / 支付宝 / 他款 App）
- 自动记账（读系统支付通知）
- 语音记账 / OCR 拍照识别小票
- 多账本 / 多人共享账本
- 多币种
- 分期管理 / 报销管理 / 退款 / 手续费 / 优惠券
- 存钱目标模板（365 存钱法 / 52 周存钱法）
- 收支日历视图
- Excel / CSV 导出、账单导入回灌
- 密码 / 手势 / 指纹锁

### 专注与时间侧缺失

- **番茄钟 / 专注计时**（三款竞品都有）
- 白噪音 / 背景音
- 自习室 / 排行榜 / 互相监督
- 锁机 / 学霸模式 —— `载体受限`
- 专注时长统计与科目分布
- 倒数日（纪念日 / 考试 / 截止日）
- 常驻提醒（不完成一直响）
- 日历 / 月 / 议程 / 看板 / 时间线视图
- 子任务 / 优先级 / 标签 / 过滤器
- NLP 自然语言建任务

### 内容与激励侧缺失

- 图片 / 附件（明确不支持，是主动设计）
- 热力图 / 日历化历史可视化
- 补卡 / 历史记录编辑
- 成就 / 徽章 / 收集图鉴 / 游戏化激励
- 养成型情绪反馈（小日常的成就卡片、喵喵的猫咪）
- 微习惯拆解 / AI 行为教练
- 协作：共享清单、任务指派、评论

### 平台与生态侧缺失

- 桌面 / 锁屏小组件 —— `载体受限`
- 多平台客户端（仅微信小程序一个端）
- 深色模式
- 写入 iOS 健康 / 系统日历
- 第三方日历双向同步（Google Calendar 等）
- 外部工具链（MCP / CLI / 自动化）
- 横幅统计 / 通知栏快捷记账 —— `载体受限`

> **载体天花板提示**：上表标 `载体受限` 的 4 项，是小程序架构的硬限制，不是开发优先级问题。钱迹（自动记账）、番茄 ToDo（学霸模式锁机）、小日常（桌面小组件）的核心卖点都建立在「原生 App」之上。若长期只做小程序，这几张牌**必须放弃或换打法**（例如用「微信服务通知 + 分享卡片」替代小组件触达）。

## 5. 优势：我们确实更好用的地方

这一节决定了差异化该往哪押。

### ① 跨模块聚合：今日页 + 月报 + 统一搜索（6 款竞品都没有）

「今日概览」把**日程 + 习惯 + 待买**合并成一张「统一待处理」清单，可快速完成与置顶，日程逾期有明确标识；「月报」把**收支 + 预算 + 习惯达标率 + 日程完成率 + 体重变化 + 书影音 + 随记次数/天数/常用标签/心情分布**合成一页；「搜索」一次覆盖随记、日程、待买、书影音、账本五个集合。

对照：滴答清单的「今日」只含任务与习惯，不含财务；钱迹的年度报告只含财务；小日常只有习惯与待办。没有任何一款做到了**「钱 + 习惯 + 生活」同框**。这是我们的结构优势，目前只发挥了一半。

### ② 真正数据自主 + 隐私边界干净（强于鲨鱼 / 喵喵）

- **自建后端**（Express + MySQL + WS），数据不在第三方 SaaS 上；`LWW` 冲突策略 + 软删墓碑 + 增量 `GET /api/sync?since=`，同步协议可给未来网页版复用。
- **明确不接收图片 / 音频 / 文件，不接入任何第三方金融数据**——这是主动的隐私设计，不是能力欠缺。
- **AI 默认关闭**，只有用户主动开启后才由服务端发送**裁剪后的摘要**；关闭即停止第三方调用并清除缓存文案；密钥不进代码、服务端密文存储。
- **无广告、无开屏、无社区、无理财导流**——与钱迹的「三无」同档，明显优于鲨鱼（开屏广告 + 理财课/券商导流）与喵喵（广告关闭按钮隐蔽、需「后台深度应用权限」引发隐私投诉、黑猫投诉 973 条）。
- **分享卡片隐私化**：12 个页面支持转发/朋友圈，但卡片只用固定中性文案、显式指定包内 logo，**不会把记账页/时间线截图带出**——竞品普遍用页面截图当分享卡，这在记账场景是真实泄露风险。

### ③ 离线韧性与写队列的工程完成度

先渲染后拉（杜绝白屏）、乐观更新立即生效、失败进队列 15 秒自动重试、被服务端 4xx 明确拒绝时**丢弃队首并记入可见状态**（「我的 → 数据状态」展示原因 + 手动重试，而不是无限重试刷屏）、WebSocket 推送 + 断线指数退避 + 60 秒兜底轮询、本地缓存 1MB 上限前的无损瘦身与「重建本机缓存」自救。

这套东西在竞品里**属于看不见的部分**，但直接决定「弱网/离线时会不会丢数据、会不会骗用户」。轻量记账 App 常见的「网络差时启动极慢、记账卡住」（横评中挖财、有鱼记账都被点名）我们不会有。

### ④ 生活化中文分类，比通用分类更贴地

支出 28 项里包含 `买菜`、`水果零食`、`打车出行`、`房租房贷`、`订阅会员`、`银行手续费`、`公益捐赠`、`家庭育儿` 等中国生活场景分类；账户预设直接给了**花呗 / 美团月付 / 抖音月付 / 京东白条**——这些是「中国年轻人的真实负债结构」，比通用「信用卡」一项更可用。

> 注：固定不可改是缺点（见 §3），但**分类本身的设计质量**是加分项。

### ⑤ 健康量化闭环 + 双周/月复盘，竞品空白区

体重/体脂记录 + canvas 手绘折线（7 日/30 日 + 7 日均线）+ BMI 区间着色 + 目标进度 + 热量缺口 + 自定义周健身计划，再叠上月报里的「月内体重变化」。记账类竞品完全不做健康，待办类竞品只做专注时长。**「记账 + 健身 + 体重」同 App 是空白位**。

### ⑥ 零安装 + 微信生态分发

竞品全部要求下载 App（几十 MB、注册账号、看开屏广告）。我们「点开即用」+ 12 页转发/朋友圈，**获客成本结构性更低**——对小红书起号阶段是最实用的分发杠杆。代价是牺牲了小组件、自动记账、锁机、健康数据写入（见 §4 载体天花板）。

### ⑦ 主题随账号同步（细节优势）

4 套低饱和主题（雾林/暖纸/月白/暮紫）随 `settings` 记录**跨设备同步**，页面、主按钮、资料首屏、底部导航与系统导航栏即时联动。多数 App 的主题只是本机偏好，换设备会丢。

## 6. 改进建议（按性价比排序）

以下为**建议**，非结论。判断依据：能不能补上「留存引擎」、能不能兑现「数据自主」承诺、成本是否可控。

| 优先级 | 建议动作 | 为什么做 | 成本 / 依赖 |
|---|---|---|---|
| **P0** | **补齐提醒矩阵**：习惯打卡提醒、每日日程提醒、账单还款提醒、待买提醒 | 我们唯一可用的推送通道是微信订阅消息，而订阅消息是**一次性**授权，需要「一次订阅 → 多次触达」的额度管理设计。这是留存的第一杠杆：竞品的提醒正是让用户「还记得打开」的机制。当前「习惯」完全没有提醒，等于把连续天数交给用户记忆 | 服务端加定时任务 + 订阅消息发送；前端补订阅引导与额度提示。中等 |
| **P0** | **导出 Excel/CSV + 增加导入入口**（至少支持自家 JSON 回灌 + CSV） | 「数据自主」是我们的核心差异，但「能导出不能导入」是半成品。用户对记账 App 的硬需求包含「导出表格自己分析」与「换机不丢数据」。补齐后可以把这句承诺写进宣传语 | 前端导出/解析 + 服务端批量 upsert 接口。低～中 |
| **P0** | **分类可自定义**（增删/排序/图标，二级分类可选） | 28 项固定分类是双刃：设计质量高，但「每笔都要在 28 项里选」正是横评里 62% 用户放弃记账的原因（决策疲劳）。允许用户把常用分类提到前面、隐藏用不到的，**比继续加分类更能提升坚持率** | 新增分类集合 + 排序字段 + 设置页管理。中等 |
| **P1** | **习惯补卡 + 热力图 + 徽章体系** | 直接对标小日常的强项，且是纯前端 + 少量数据的低成本项。热力图让「坚持」可见，补卡消除「断一次就放弃」的全有全无效应（研究显示断掉 100 天打卡的人会把中断体验为「真正的失去」） | 低。可在一次迭代内完成 |
| **P1** | **番茄钟 / 专注计时，绑定日程与习惯** | 补上「日程 → 专注 → 习惯」的闭环，这是滴答/番茄 ToDo/小日常三款都有的能力，而我们完全空白。小程序内可实现（页面内计时 + 记录专注时长），锁机做不了但可以不做。专注时长还能进月报，强化跨模块联动 | 中。注意小程序后台运行限制 |
| **P1** | **深色模式** | 6 款竞品全部支持。现有 CSS 变量体系可平滑迁移，投入产出比很高，且影响「夜间记账/睡前打卡」这一高频时段的第一印象 | 低。`app.json` darkmode + theme.json |
| **P1** | **记账日历视图 + 报表形态丰富** | 补上与钱迹/鲨鱼的视觉差距。日历视图是记账 App 的「回顾入口」，比多一张饼图更有用 | 低～中 |
| **P2** | **把「聚合」升级为「联动」** | 这是把一体化从「列表堆在一起」变成「互相驱动」的关键：预算超支 → 待买清单首页提示降级；习惯连续 3 天未达标 → 日程自动建议降低目标；体重连续上升 → 热量缺口卡前置。竞品结构上做不到，只有我们能做到——**这才是真正的护城河** | 中～高。需要产品设计而非堆功能 |
| **P2** | **应用锁（页面内口令）** | 小程序拿不到指纹，但可以做「进入需输入 4 位口令」的软锁。对记账隐私敏感用户有实际价值 | 低 |
| **P2** | **战略层：是否补一个原生壳** | 若长期要做「小组件 / 自动记账 / 锁机 / 健康数据写入」，必须做 App（或用 uni-app / RN 多端）。建议先靠小程序验证留存，再决定是否投入原生 | 高。属于路线决策，非功能 |

### 不建议做的

1. 不要跟钱迹比记账深度（对方 600 万用户、9 端、8 年迭代，正面拼必输）；
2. 不要跟喵喵比游戏化（其商业化争议大、黑猫投诉 973 条，路径不健康）；
3. 不要为了「功能多」而加协作/社区——我们的隐私干净是无广告定位的一部分，加社交会稀释它。
